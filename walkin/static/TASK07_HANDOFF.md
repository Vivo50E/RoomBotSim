# TASK-07 handoff

## Console/API contract

The static console uses the existing API unchanged: `POST /upload`, `GET /status/{job}`,
`POST /confirm/{job}`, `GET /test`, `WS /ws/{job}`, episode start/stop/list endpoints,
and `POST /sft/{job}`. WebSocket state supplies `world`, people, robots, objects, and
`episode.last_action`/`last_result`. Human controls send `teleop` and `skill` messages;
the runtime writes its existing episode JSONL/SFT schema.

## QR handoff

`qr.png` is a valid, decoded QR for `http://10.104.4.240:8000/`, the LAN address detected
on this machine. Run `python static/generate_qr.py http://LAN.IP:PORT/` after a network or
port change. `QR_README.md` documents the LAN server requirement and generator.

## Verification run

From `walkin/`, with the server on `127.0.0.1:8000`:

```sh
python static/verify_task07.py --url http://127.0.0.1:8000 --exercise-human
python -m py_compile static/verify_task07.py static/generate_qr.py
node --check /tmp/task07-syntax.js  # generated by the documented inline-script extraction check
```

Passed on this machine: QR decoded to the LAN URL; first-paint canvas bitmap matched its
CSS size; desktop demo/live websocket and phone uploader passed; 7x9, 20 m, and corridor
fit invariants passed; and a real Playwright Human run produced exactly one visible
`navigate_to` before `pick`, with no page errors. The runtime JSONL contained the
teleop `[t,v,w]` samples on that navigate step and the normal subsequent skill record.

## Boundary note

No backend change was made. One backend-only polish item observed during the live run:
`Runtime.start_episode()` does not reset `ep_t_step` before a Human teleop segment, so the
recorded `duration_s` for that consolidated navigation can include time before the episode.
The samples, ordering, JSONL schema, and SFT export are correct; resetting that timer in
`walkin/server.py` would make the duration precise, but is outside the static-only boundary.
